# Redline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Redline — two Forge apps (Core for Jira/Confluence/Rovo/MCP, and Bitbucket) on a shared, fully tested
TypeScript domain core — that produces cited threat models, turns them into requirements, and enforces them at Done
and at merge via signed attestations.

**Architecture:** pnpm monorepo. `packages/*` hold pure, Forge-free domain code (types, crypto, frameworks, core
logic, prompts, SQL) behind ports; `apps/core` and `apps/bitbucket` are thin Forge adapters plus a Custom UI.
The live review runs through the Rovo agent from a Jira Automation rule; its JSON answer is ingested by deterministic
code that resolves citations, adds a rule-based baseline, scores, and writes a verdict that the gates read.

**Tech Stack:** Node 22, TypeScript 5 (strict), pnpm workspaces, Vitest, zod, `@noble/ed25519` + `@noble/hashes`,
`picomatch`, `yaml`, better-sqlite3 (tests only), React 18 + Vite + Atlaskit, Forge CLI 14+ (`@forge/api`,
`@forge/sql`, `@forge/kvs`, `@forge/events`, `@forge/resolver`, `@forge/bridge`), Playwright, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-14-redline-design.md` (decisions) and
`Redline Product and Technical Build Spec.md` (product behaviour). Forge API facts: `docs/research/forge-api-notes.md`.

## Global Constraints

- TypeScript `strict: true`, `noUncheckedIndexedAccess: true`, no `any` (ESLint `@typescript-eslint/no-explicit-any: error`).
- zod schemas at every boundary: resolver input, action input, agent/LLM output, SQL rows.
- Errors crossing a port are `Result<T, AppError>`; never throw across a port.
- `packages/*` never import `@forge/*`. Only `apps/*/src/adapters` and entry files do.
- Every SQL statement is parameterized and lives in `packages/db`.
- No egress: neither manifest has `permissions.external`. No `fetch` to non-Atlassian hosts in app code.
- Logs contain only ids, timings, counts and token numbers — never excerpts, prompts or agent output.
- Severity enum exactly: `Low | Medium | High | Critical`. STRIDE enum exactly: `Spoofing | Tampering | Repudiation | InformationDisclosure | DenialOfService | ElevationOfPrivilege`.
- Threat states: `proposed | accepted | dismissed | needs_human`. Dismiss reasons: `false_positive | not_applicable | duplicate | already_mitigated`.
- Requirement states: `Open | InProgress | Verified | AcceptedRisk | NotApplicable` (NotApplicable champion only).
- Review statuses: `queued | gathering | awaiting_agent | modeling | ready | failed | agent_timeout`.
- Acceptance caps: tech lead ≤ Medium; High/Critical need a security champion; Critical expiry ≤ 30 days, others ≤ 90 days; approver ≠ requester.
- Attestation default expiry 24 h; must match PR head commit; Ed25519; key id; nonce.
- Warn-only mode auto-expires after 14 days. Break-glass: admin only, reason required, ledgered.
- Untrusted excerpt cap 2,000 chars per fact; sketch strings ≤ 200 chars; agent threat title ≤ 120, scenario ≤ 600, quote ≤ 200.
- Per-review token budget default 40,000 in / 8,000 out (pipeline path).
- Action responses < 10 s and < 256 KB. Validator < 500 ms (entity property only). Merge check < 2 s.
- Subtasks labelled `redline`. Issue property key `redline.verdict`.
- Real-model calls: `FakeLlm` in tests/CI; `ClaudeCodeLlm` only via explicit eval/tuning scripts; `ForgeLlm` off by default, never enabled without Pranav's OK.

## Review Focus

1. **Concurrent ledger appends** (two acceptances approved in the same second) must not fork the hash chain: the second insert fails on a unique `prev_hash` and retries on the new head. Test in Task 10.
2. **Agent output that is not clean JSON** (prose around it, fenced block, truncated, two JSON blocks, wrong issue key) must produce a recorded failed sample, never an exception or a partial write. Test in Task 9.
3. **PR descriptions with several or stale attestations** (older commit, other repo, edited text) must evaluate the newest attestation for this repo and report the precise failure. Test in Task 6 and Task 27.
4. **Issue moved to another project** changes its key; reviews, requirements and verdicts are keyed by issue **id** with key as a display field. Test in Task 11 (repo) and Task 18 (trigger).
5. **Huge or hostile pages** (1 MB page, zero-width characters, base64 blobs, RTL overrides) are capped, scanned and flagged without slowing ingest past budget. Test in Task 7.
